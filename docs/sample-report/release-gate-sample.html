RG-AUTHZ-010 critical EXPLOITED

Broken access control: bob can read alice's resource via GET /api/messages/{id}

Location
GET /api/messages/{id}
What this means
Any authenticated user (or another user) can read data belonging to a different account by changing the id in the URL.
Reproduce
Authenticate as bob, request GET /api/messages/1. Observed HTTP 200 and the owner-only canary 'PRIVATE-CANARY' in the response.
Suggested fix
Enforce ownership in the query or handler: scope the lookup to the caller's id (WHERE owner_id = :caller) and return 404/403 otherwise.
Reported by
—
Evidence
evidence/authz/GET_api_messages_1_as_bob.txt

RG-INJECTIO-006 high EXPLOITED

SQL injection: /api/search interpolates q into SQL (unauthenticated)

Location
GET /api/search
What this means
Anyone without logging in can alter the query. Boolean payload returned every item row. Other tables (users with password hashes, messages) are in the same database; a UNION read of them was NOT attempted.
Reproduce
GET /api/search?q=' OR '1'='1 returns all items; q=' returns 500 with sqlite error.
Suggested fix
Use parameter binding: conn.execute('... LIKE ?', (f'%{q}%',)).
Reported by
—
Evidence
evidence/sqli/search.txt, evidence/semgrep-20261018T140402Z/semgrep.json, evidence/probes.py
